# qa-api-test
Тестовое задание: API тестирование, Postman коллекция, тест-кейсы, баг-репорт

Хочу поделиться результатами и немного контекстом по тестовому заданию.
Я глубоко погрузился в документацию и составил около 90 тест-кейсов по эндпоинтам. В ходе проверки выявил довольно много багов, причем не только в самом API, но и в логике самих требований (есть моменты, которые нужно уточнять с аналитиками).
Чтобы описать все граничные случаи и задокументировать каждый шаг на 100%, потребуется значительно больше времени. Сейчас у меня плотный график в связи с прохождением технических собеседований, поэтому я применил тайм-боксинг и сфокусировался на самых критичных и показательных сценариях, чтобы вы могли полноценно оценить ход моих мыслей и подход к тестированию.

В приложенных файлах — основные находки и структура проверок. 
В файле с тест-кейсами красным цветом выделены тест-кейсы, которые не проходят (фактический результат отличается от ожидаемого). По этим кейсам можно завести баг-репорты.
В файле bug_report при необходимости к баг-репортам можно добавить скриншоты или логи для наглядности (в реальном проекте это было бы в Jira/YouTrack/другом таск-трекере). Такая детализация помогает разработчикам быстрее понять и воспроизвести проблему.
